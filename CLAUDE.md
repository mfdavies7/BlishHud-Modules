# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Guild Wars 2 modules for [Blish HUD](https://blishhud.com): **WikiSearch**, **WaypointPaste**, **TyriaSearch**, **QuickItem**, **MinimapClocks**, **ZoomOut**, **SkipCutscenes**, **ItemDestruction**, **CopyItemName**, **BlishIconManager**. Each top-level folder is an independent module project; there is no test project. `BlishHud-Modules.sln` at the root lists them all only because SSRD's builder (blish-hud/bhm-builder) runs a bare `nuget restore`, which needs a `.sln` in the module folder or its parent; a new module must be added to it. Each module's `<Module>/README.md` is its user-facing doc and lists every setting with its default — keep it in sync when settings change. The root README.md is a brief overview (module table, build, credits); a new module gets a row there. Each module's `<Module>/profile/` holds what's pasted into its SSRD (Blish HUD's release portal) profile: `summary.txt` (plain text, 200 characters max), `hero.png` (square PNG, 192–256 px), `icon.svg` / `icon-64.png` / `icon-32.png` (the corner icon as vector and raster; `ref/textures/<Module>.png` is the 64 px one, used as the settings window emblem, and `ref/textures/<Module>-32.png` is a copy of `icon-32.png`, used for the corner icon and Wiki Search's Shift hint), `profile.md` (the player-facing module page) and `release-notes.md` (what's new in the current version, 800 characters max as pasted; replace it when bumping `version` in manifest.json). It isn't packed into the `.bhm`; keep it in sync with the README when features or settings change.

Icon style matches Blish HUD's own corner icons, Event Table, Bag of Holding and GW2's menu icons: flat parchment silhouettes in Blish HUD's exact logo colours (`ref/logo.png` in its repo: face `#fff7de`, second plane `#cec7ad`), edges and detail lines black (`#000000`) about 2.3–2.6 units wide in the 64-unit viewBox (≈1 px at 32 px, never thick outlines), a soft drop shadow (`feDropShadow` dy 0.9, σ 1.3, 70 % black), no glossy highlights. Each corner icon also has a hover picture, as Blish HUD's `logo-big.png`: the same drawing in white (`#ffffff`) and grey (`#c6c6c6`), scaled 32/28 about the centre so it fills the 32 px (`ref/textures/<Module>Hover-32.png`, and `<Module>DisabledHover-32.png` for modules with a disabled icon), passed to `RegisteredCornerIcon` as `HoverIcon`. Every size (icon.svg, icon-64/32, the `ref/textures` copies, `*Disabled-32.png`, the hover pictures, hero.png and BlishIconManager's Folder.png) is rendered from one SVG per module by `gen_icons.py` (kept in `../BlishHud-Modules-icon-backup-2026-11-25/` with the pre-restyle icons; needs `pip install resvg-py pillow`).

## Build

Requires the .NET SDK. Each module builds on its own:

```
dotnet build WikiSearch -c Release
dotnet build WaypointPaste -c Release
dotnet build TyriaSearch -c Release
dotnet build QuickItem -c Release
dotnet build MinimapClocks -c Release
dotnet build ZoomOut -c Release
dotnet build SkipCutscenes -c Release
dotnet build ItemDestruction -c Release
dotnet build CopyItemName -c Release
dotnet build BlishIconManager -c Release
```

The BlishHUD NuGet package's build targets pack `<Module>/bin/Release/bytex.<module>_<version>.bhm` (DLL + `manifest.json` + `ref/` assets; the version is the one in its `manifest.json`). To try it, copy the `.bhm` into `Documents/Guild Wars 2/addons/blishhud/modules`. To build and install, run `powershell -ExecutionPolicy Bypass -File .\deploy.ps1` from the repo root, which handles every module (any folder with a `manifest.json` and a csproj). Add module names (`.\deploy.ps1 QuickItem WikiSearch`) to do only those. It removes other versions of the same module from the modules folder and exits 1 if a build fails. Use it whenever asked to build, deploy or install the modules. There are no automated tests; verification happens in game.

## Project layout conventions

- Target `net472`, `LangVersion latest`. BlishHUD (and its deps: MonoGame, Gw2Sharp, Newtonsoft.Json) is referenced with `ExcludeAssets="runtime"` because Blish HUD supplies them at runtime — don't bundle them.
- `Shared/*.cs` is compiled into every module via a `<Compile Include="..\Shared\*.cs" Link=...>` item in each csproj (namespace `Bytex.ModuleShared`, all `internal`). A new module needs that same item group.
- C# namespaces start with `Bytex.`: each module's code is in `Bytex.<Name>` (and its csproj `RootNamespace` matches).
- Build output is named `bytex.<name>`, the module name in lowercase (`bytex.wikisearch`), the same as the manifest namespace: the csproj sets `AssemblyName` (the DLL) to it, and `BlishHUDModuleFileName` (the `.bhm`) to it plus `_<version>`, which the csproj reads from manifest.json at build time, so bumping the version there is enough.
- Each module has a `manifest.json` (namespace `bytex.<name>`, `package` = DLL name, dependency `bh.blishhud ^1.3.0`) and a `ref/` folder for textures loaded via `ContentsManager`.
- Entry point is a `[Export(typeof(Module))]` class `<Name>Module : Module` that defines settings in `DefineSettings` and wires up UI/hotkeys in `Initialize` (plus `OnModuleLoaded`/`Update` where needed), cleaning up in `Unload`.

## User-facing text

- Module names in anything a player sees (UI, notifications, log messages, README) are spaced: "Wiki Search", "Waypoint Paste", "Tyria Search", "Quick Item", "Minimap Clocks", "Zoom Out", "Skip Cutscenes", "Item Destruction", "Copy Item Name", "Blish Icon Manager". The PascalCase forms are only for code, folders and DLLs.
- Labels use Title Case: setting names, section titles, buttons, menu items, window and panel titles, dropdown entries, portal kind labels ("Show on Map", "Key Press Delay (ms)", "Asura Gate"). Leave articles, short conjunctions and short prepositions lowercase unless they come first (a, the, and, or, to, on, in, of, for, from, into).
- Tooltips, status lines and messages are sentences in sentence case. When one names a setting or action, use its exact Title Case label ("raise Key Press Delay in the settings").
- `AbortException` messages are full sentences starting with a capital, because they're shown as "<Module name>: <message>". Keep them short (about 45 characters): a notification banner shows one line and cuts off the rest. Put longer advice in the README's troubleshooting section, not in the message.

## Shared code

- `ChatInput` — simulated keystrokes into GW2 chat. Keys are sent system-wide, so every stroke calls `EnsureSafe(chatOpen)`, which throws `AbortException` (message shown to the player) if GW2 lost focus, left the game, or chat open/closed state changed. Preserve this check in any new input sequence.
- `ModuleLifetime` — whether the module is loaded: every module calls `ModuleLifetime.Begin()` first in `LoadAsync` (Waypoint Paste in `Initialize`) and `ModuleLifetime.End()` first in `Unload`. `EnsureSafe` throws once it has ended, so no key or click is sent after unload, and `Notify` shows nothing then. Work that isn't a keystroke checks `ModuleLifetime.Ended` / `ThrowIfEnded()` before touching objects Unload disposes (a lookup client, a texture for the hint).
- `FileWriter` — saves a file off the update thread (one write at a time, newest text wins); `Flush()` writes what's waiting synchronously, called from `Unload`. Used for Blish Icon Manager's layout, Quick Item's bars and Tyria Search's learned portals; don't write files from Update, draw or input handlers.
- `ChatActions` — higher-level sequences built on `ChatInput`: focus the game, insert text into chat via clipboard, whisper to self (then reset chat channel to `/s`). Used by WaypointPaste and TyriaSearch.
- `Blocked` — call `Blocked.Check(ex, path)` in a failed save's catch (or `Blocked.Check(ex)` for a failed download). If security software blocked it, Blish HUD tells the player, once for each kind. A module that uses it sets `Blocked.ModuleName` (spaced) in its constructor.
- `SettingsWithValuesView` — replaces Blish HUD's settings panel (which can't be extended) so whole-number sliders get a typeable value box and a Default button (greyed out at the default), with optional buttons below, or in titled sections (`SettingsSection`). Every module's settings live in its own `StandardWindow` (opened from the corner icon), which shows this view; TyriaSearch's is sectioned — a new TyriaSearch setting must be added to a section in `SettingsView()` or it won't appear.
- `RegisteredCornerIcon` — the module's corner icon, driven by its Register Corner Icon setting the way Estreya's Event Table does it: off removes (disposes) the icon instead of hiding it, and disables the Corner Icon Left/Right Click Action settings. `Icon` is null while unregistered. It takes the module's manifest: the icon's `IconName` (its tooltip) is the manifest name, and its `Priority` is fixed from the namespace; `ShowKeybind(setting)` puts that hotkey after the name in square brackets in `IconName` ("Wiki Search [Ctrl+W]", while bound, following `SettingChanged` and the binding's in-place `BindingChanged`), since Blish HUD sets the tooltip from `IconName`; every module but Blish Icon Manager shows its main hotkey. `SetTextures` swaps the picture and its hover picture together (e.g. for a disabled icon) (`PriorityFor`, FNV-1a into ±1e9), so Bag of Holding, which remembers icons by priority, keeps them between sessions.
- `SliderSettings.DefineSlider(key, default, name, description, min, max)` — defines every whole-number slider setting (in place of `DefineSetting` + `SetRange`) and remembers its default, which Blish HUD doesn't keep, for the Default button.
- `SettingsUsedWhen` — greys out settings that only matter while a condition holds (`new SettingsUsedWhen(() => _x.Value, deps...).On(_x)`, disposed in `Unload`). Blish HUD only reads a setting's disabled state when its view is built, so always disable through `SettingsUsedWhen.SetDisabled` (not Blish's `SetDisabled`): it raises `DisabledChanged`, on which `SettingsWithValuesView` rebuilds that row so an open settings window updates.
- `Notify` — shows "<Module name>: <message>" as Blish HUD screen notifications. The banner is one line in a fixed 1024 px box, so a message too wide for it (measured in Menomonia 36) is split at word breaks over several banners. Every module shows all its notifications through it (each has a `ModuleName` constant, spaced); don't call `ScreenNotification.ShowNotification` directly.
- `OpenSettingsView` — what every module's `GetSettingsView` returns: just a centred Settings button that opens the module's settings window.
- `HintBox` — the game-tooltip-style hint that follows the cursor (`PlaceNearCursor`); icon, title (and its colour) and description can change while shown. Wiki Search, Copy Item Name and Item Destruction use it.
- `ClickedLink` — reads the link GW2 put in chat on a shift-click (`TakeAsync`, Wiki Search's algorithm: Shift+Home, copy, then Ctrl+A, copy), or takes it out again (`TakeOutAsync`), pasting back only the player's other text, or, if chat was closed before, emptying it and closing it with Enter as TyrianQoL does (Escape would close the inventory first; unsent text is lost, as Enter would send it). `WaitForChatAsync` runs first: if chat was open but the click took its focus, Enter focuses it again and it counts as closed. Item Destruction always closes chat, as an open chat hides the destroy box opening.
- `ShiftClickClaim` — which module shift-clicks belong to right now, kept in AppDomain data because each module compiles its own copy of Shared. Copy Item Name and Item Destruction claim them while turned on (and turn themselves off when the other claims); Wiki Search doesn't search while another module has the claim.
- `ClickedLink.NameOf` — the name and amount in a link copied as its name ("[250 Mithril Ore]"; a number before "Slot" stays, for bags); null for a chat code. That text is the game's own, in its language, so it always comes first.
- `Shared/Links/LinkLookup.cs` — the fallback when chat gives a chat code: code → kind, id, amount, and name/icon/rarity from the GW2 API (one request per link, cached for the session). The game's language can't be read (Mumble doesn't report it, Local.dat is an archive), so both modules have a Backup Name Language setting (`BackupLanguage`, default Blish HUD Language, i.e. Blish HUD's language setting), described as used only for this fallback. It needs `System.Net.Http`, so it's in a subfolder that only Copy Item Name and Item Destruction compile (their csproj adds `..\Shared\Links\*.cs`). `Shared/Links/IconCapture.cs` (needs `System.Drawing`) is there too: the picture of the shift-clicked icon both modules show in their hint.

Clipboard is used for typing text. Whenever a module uses the clipboard behind the player's back (typing into chat), it always saves and restores the previous contents; there's no setting for it. Only actions whose point is to copy something (like Copy Chat Link) leave their text on the clipboard.

## TyriaSearch architecture

The largest module. Data flow:

- `Gw2Data` downloads and caches search data: places/skills/traits and items from the GW2 API (per language), NPCs from the wiki's Semantic MediaWiki `ask` API (English only). Caches are `search-*.json` files in the `tyriasearch` directory (declared under `directories` in manifest.json); full refresh every 30 days, otherwise only incremental updates after a game build change (fingerprint of map/skill/trait id lists). `SearchWikiAsync` is the live wiki search: appended below local results in the Everything category, a fallback when nothing matches in others. Things without an API icon get the wiki's `Has game icon` (looked up by game id for skills/traits/items, read alongside NPC and live page queries).
- `Places` resolves map coordinates / nearest waypoint; `WikiEntries` turns wiki NPC/page data into `SearchEntry`s (exact vs approximate area-centre positions).
- `SearchIndex` is an immutable index built off-thread and swapped into a `volatile` field on the module, so the UI reads it each frame without locking.
- `SearchWindow` / `ResultRow` are the UI; `ResultAction` enum maps clicks to actions (copy/paste/whisper chat link, show on map, wiki, favourite, menu). `MapMarker` draws the "Show on map" marker on the world map, clamped to screen edge when off-screen.

## QuickItem architecture

- `IconFinder` finds an item's icon in a screenshot in pure C# (no native code): coloured zero-mean normalised correlation, coarse search at ~14 px icons, then a fine search around the best 12 spots (position at the expected size, then each size ±2 px around that), the likeliest spot first and stopping there if it scores under `goodEnough`. Templates are cached per icon and size, and store only their masked pixels as offsets. It has no Blish HUD dependency, so it can be tested on saved screenshots outside the game (~60–80 ms for a 1080p search). Score 0 is exact; real matches score about 0.00–0.02 and other icons 0.1 or more (Match Tolerance default 7 = 0.07).
- `ItemUser` runs a use: focus the game, search; if not found and the inventory isn't already open, press Inventory Key and poll every 30 ms (scoring only the emblem at its known place) until the window is fully drawn (emblem ≤ 0.03 and the slot column unchanged between two looks), then search once — or search the last frame when Wait for Inventory runs out; if still not found and Scroll the Inventory is on, scroll up to the top then down to the bottom, after each step waiting until the smooth scroll settles (`SettleAsync`) and searching only if it moved (ends detected by the first slot's column, three slots up and down, no longer changing), double-click (leaving the inventory scrolled where the item was; it scrolls back only if the item wasn't found), close the inventory if it opened it, put the cursor back. Between wheel turns and after the double-click the cursor is parked in the client area's top right corner (`ParkCursor`), and only restored to the player's position when the use ends. Every key and click calls `EnsureSafe(chatOpen: false)`. Each use's steps and timings are logged when it ends (Info while Save Search Screenshots is on, else Debug); screenshots are saved on a background queue so PNG encoding (~0.35 s) doesn't slow the use.
- The inventory window is found by its emblem (`ref/textures/InventoryEmblem.png`, the bag at its top left, cropped from inside so no background shows) with `IconFinder` (no slot mask, ±15% size); it scores 0.00 open, around 1 at its place while fading in, 0.3+ elsewhere (tolerance 0.2). `InventorySpot` works out the slot size and the first slot's centre (the scroll point) from the matched emblem. The last place is kept in memory for the session and checked first with `IconFinder.ScoreAt`; when that fails a full search (~0.15 s) runs before Inventory Key is pressed (the player may have moved the open window, and the key would close it), and while waiting for the window to open once it hasn't appeared at its last place within 600 ms. The key is pressed again to close the inventory only if the window was seen.
- Blish HUD's `Mouse.RotateWheel` takes the distance modulo 120 and sends nothing for a whole notch, so wheel turns are sent as ±119, one call per notch (TyriaSearch does the same).
- `ScreenGrab` captures the game window's own client area with `PrintWindow(PW_RENDERFULLCONTENT)`, so Blish HUD's overlay isn't in it. After 3 blank captures in a row it falls back for the session to copying the screen over the client area, with the bars hidden. Bars are otherwise hidden only if one covers the spot about to be clicked (`BarAt`). `IconCache` downloads icon PNGs from the render service into `quickitem/icons` for their pixels; bars draw icons from Blish HUD's asset cache (`AsyncTexture2D.FromAssetId`).
- `BarStore` saves layouts and bars to `quickitem/bars.json` (version 2: `{layouts, bars, chosenLayout}`; a version 1 file, a bare array of bars, is moved into the first layout "Main" on load). A bar's `layout` is its layout's id, or null for every layout. The layout shown is a hand-picked one (kept until the character changes), else the one set for the character, else for its profession, else the last chosen; only the hotkeys of items on bars in use are registered, so a key can mean different items per layout. `LayoutsList` is the layout editor inside the settings window's Layouts section (`SettingsSection.BuildExtra`). `BarControl` draws a bar and handles editing (drag header/items, right-click menus). `ItemPicker` lists the ready-made actions first, then the player's items via the API (account, characters, inventories, all optional), or looks one up by chat link or id.
- A `BarItem` with `Action = "deposit-materials"` (no icon) presses the inventory's Deposit All Materials button: `ItemUser` opens the inventory if needed, finds the button (`ref/textures/DepositMaterials.png`, its middle; 0.00 open, 0.4+ for anything else) in a strip right of the emblem 0.93 slots below it (its x depends on the window's width), single-clicks it and closes the inventory if it opened it. Below 16 px the strip is searched at twice the size. It's also on the Deposit All Materials Hotkey setting.
- Quick Item is off in PvP and WvW (`InPvp`: Mumble's competitive flag or a PvP/WvW map type, lobbies included): bars hidden, every hotkey disabled so keys reach the game, the corner icon swapped for `ref/textures/QuickItemDisabled-32.png`, and `ItemUser` aborts at its next step (`EnsureAllowed`). Disabled icons (Wiki Search's too) are the normal 32 px icon with each pixel grey at 1.5 × (luminance − 118), clamped to 0–255, and alpha × 0.7.

## Modules from TyrianQoL

Minimap Clocks, Zoom Out, Skip Cutscenes, Item Destruction and Copy Item Name are rewrites of the remaining features KenediaDev's TyrianQoL ships (its AutoSniff, Schematic Processing and Enhanced Crosshair are disabled or unfinished there, and the first two are unattended automation, so they aren't recreated).

- **MinimapClocks** — `TimersPanel` draws all lines as one control: In the Minimap (inside its left edge) where TyrianQoL's Game Resets puts it (left edge at screen width − 1.1 × Mumble's raw compass width, bottom 60 px above the screen bottom, or with the compass at the top, compass height + 24 × scale, scale = height / 362, less 0.3 below 0.5), or draggable anywhere (position in a hidden `Position` sub-collection; X is the edge Align Text lines up, so the timers grow from it). Lines are aligned by Align Text; the panel's width is measured with every digit as 0 so it doesn't change as seconds tick. Dragging ends on Blish HUD's global left release (the overlay doesn't see the button state itself). Text Style Like the Game's Clock (default) draws each character at its own width (Blish's fonts have LetterSpacing −1, which crowds Menomonia), twice 1 px apart, over a soft black shadow, to match GW2's clock under the minimap; Outlined draws it as TyrianQoL does: white with a 1 px black outline (`DrawStringOnCtrl` stroke), 2 px around each line, 4 px between lines; Small is Menomonia 14 (Blish HUD's default font, TyrianQoL's), Medium and Large two and four sizes up. Days in Words and Clock drops "0 days" on the last day. Line order is a hidden `Order.Lines` setting (comma-separated `LineKind`s, missing ones appended), Each line's settings (Show, under its old key `ShowLocalTime` … `ShowWvwReset`; Show Icon, Show Name, Colour, 24-Hour Clock or Countdown Format, Remind Before Reset, WvW Region) are a `LineSettings` (keys `<LineKind><Setting>`), shown in a section per line, in line order between Timers and Look; its Move Up / Move Down (added through `BuildExtra`) change the order and re-sort the open window's sections in place (`FlowPanel.SortChildren`). There are no shared look settings for lines. It captures `Mouse` only while draggable (Anywhere with Lock Position off); otherwise `Mouse | DoNotBlock` with Show Tooltips on, so hovering shows tooltips and clicks still reach the game, or `None` with it off. Kept a strict superset of TyrianQoL's Game Resets (`../Kenedia.BlishHUD/QoL/SubModules/GameResets/GameResets.cs`): its Edit Position / Show Tooltips / Long format map to Lock Position / Show Tooltips / Days in Words and Clock. Daily 00:00 UTC, weekly Monday 07:30 UTC, WvW NA Saturday 02:00 / EU Friday 18:00 UTC. Icons are game assets (clock 517180, Wizard's Vault daily 42684 and weekly 602781, WvW 338457).
- **ZoomOut** — presses the game's Zoom Out key one press per Key Press Delay, watching Mumble's camera-to-character distance, until it stops growing (Furthest) or reaches the baseline (Where You Had It, waiting for the camera to settle after each press). Triggers: map change, character change, mount change, and the camera pulled in (below 85 % of the baseline) while the character stands still. The baseline is the settled distance after the player zooms (wheel over the game, or their zoom keys) or after a zoom out. Never presses with chat or the map open, nor on its own with the cursor hidden unless In Action Camera is on (Zoom Out Fully, the player's, always works in action camera); a zoom out that barely moves the camera marks it blocked until the camera gets further out, and leaves the baseline alone. Kept a strict superset of TyrianQoL's Zoom Out (`../Kenedia.BlishHUD/QoL/SubModules/ZoomOut/ZoomOut.cs`): its Zoom On Camera Change / Zoom On FoV Change / Allow Manual Zoom / manual max zoom key map to When the Camera Is Pulled In (with Only While Standing Still off for its while-moving behaviour) / the same / Allow Manual Zoom (off undoes the player's zoom in after it settles) / Zoom Out Fully Hotkey.
- **SkipCutscenes** — only acts while Mumble isn't ticking, after having been in game. `ScreenCheck` copies the top and bottom 5 % bands (less an eighth of the width at each end, where overlays put icons) and the middle 40 % off the screen every 250 ms: a cinematic is dark bands (bottom allows subtitles) with a non-black, moving middle for 3 looks; a vista is a moving, unletterboxed picture within 4 s of Mumble stopping, with the player's last continent position within 25 units of a vista (`Vistas`, from the API per map; a 404 map is unknown, other failures retried after a minute). TyrianQoL's catch-all (everything changing right after in game) is kept as the opening run: unletterboxed, moving from the first look for 4 looks within 4 s, any other look ending it for that stop; one Escape, counted as a cinematic away from a vista, needing both switches where vistas are unknown. Before the first in game of the session only a new character's intro is looked for: `StrictlyLetterboxed` (full-width bands, no corner inset) and moving for 6 looks, Escape only. Shift sets watch only while a candidate is on screen (not while typing a name). The click is guarded in layers (`ClickAllowed`): after in game, once per stop, never once `_menuSeen` (a moving unletterboxed look outside the opening run, i.e. character select/creation) this stop, only within the checked bottom band, and a fresh strict look right before the press. Skips with Escape, then if still a cinematic clicks the bottom right (50, 35 × UI scale from the corner) and restores the cursor. Holding Shift marks the current stop as watched.
- **ItemDestruction** — the name is `ClickedLink.NameOf` the shift-clicked link; only a chat code goes to `LinkLookup`. The hint's picture comes from `IconCapture` (`Shared/Links`): right on the click, the area around the cursor is cut from the game window's own picture (`PrintWindow(PW_RENDERFULLCONTENT)`, as Quick Item's `ScreenGrab`), so Blish HUD's overlay and the hint aren't in it; if that's blank or fails the screen is copied instead with the hint hidden for 50 ms (the module's `hideHint` callback), and after 3 in a row only the screen for the session, as Quick Item does, and of the squares of the slot frame's expected size ±3 (icon 45/50/56/62 px by UI size × DPI scale, as Quick Item, plus 2 px of frame lines each side) that contain the cursor, the one whose four sides are the clearest 1 px lines (each pixel's smaller step to its outside and inside neighbours; weakest side counted double) is taken and the frame cut off (2 px per 54); below 12 it's centred on the cursor, as TyrianQoL does. Steps ChooseItem → Reading → DragOut → Typing → Confirm. The destroy box is detected as TyrianQoL does, by a text box taking focus: `WatchForDestroyBox` runs every Update and, in DragOut, takes Mumble's IsTextInputFocused going false → true within Wait for Destroy Box of a left release (Shift up) as the box, not counting one opened after Enter, then pastes the name and restores the clipboard. It never clicks Yes. The box closing ends the item.
- **CopyItemName** — one shift-click → `ClickedLink.TakeOutAsync` → `ClickedLink.NameOf`, or for a chat code `LinkLookup` → clipboard. Formats are Name, Amount and Name, [Amount and Name] and Wiki Link (on the wiki in Backup Name Language); there are no Chat Code or ID formats, as chat normally gives the name. The copied text stays on the clipboard (that's the point); if nothing is copied the previous contents are restored. The hint shows the last copied name (rarity colour when `LinkLookup` gave one) with an `IconCapture` picture of the clicked icon, taken as Item Destruction does (skipped while Show Hint While On is off). Show Hint Only While Shift Is Held (off) shows it only while Shift is down or a copy runs, as TyrianQoL does.

## BlishIconManager architecture

Takes over Blish HUD's corner icons (Blish HUD 1.3.0's `CornerIcon`: a private static list, laid out by `UpdateCornerIconPositions` at x = 320 + `CornerIcon.LeftOffset`, 32 px each, highest `Priority` first; `OverlayService.Update` rewrites `LeftOffset` every frame in game, 36 px per TacO / SotO / Chinese client).

- `IconRegistry` finds every `CornerIcon` among `SpriteScreen.Children`, hides the real one (`Visible = false`, re-hidden each Update) and tracks whether its module wants it shown through its `PropertyChanged` "Visible" (Blish's combat/loading Dynamic HUD hiding comes through there too). Keys that persist between sessions: `self` (this module's icon), `module:<namespace>` for a module's only icon (so a name with its hotkey in it can change), or `module:<namespace>|<IconName's first line>` for each icon of a module with several (Mounts & More); a nameless one of those is `module:<namespace>|priority:<n>` if no other nameless sibling shares its explicit priority, else `|picture:<hash>` (waiting up to 2 s for its picture), else `|icon` (#2… by order). When a module's second icon is identified, named or not, any sibling keyed by the namespace alone is re-keyed at once to its own form (`IconRegistry.KeyChanged` → `LayoutStore.RenameKey`, moving its place, size, name and folder icons showing it); a lone icon keeps the name form if the layout knows that key and not the namespace one (`IconRegistry.IsKnown`) (the namespace is that of the module whose assembly defines the icon's class (Kenedia's subclass, which clicks through an `OnClick` override), else handles its mouse events, found through `Control`'s event backing fields, or `bh.blishhud` for `Overlay.BlishMenuIcon`; the module's display name is also used, as many modules give their icon no `IconName`). Only if no module is found within 2 s: `name:<IconName>`, `priority:<explicit _priority>` (reflection), else `picture:<FNV hash of pixels>`; a clash gets `#2`. On unload it restores `Visible` and calls `UpdateCornerIconPositions` by reflection.
- `IconLayer` is one screen-sized control whose `CapturesInput` is Mouse only over something it draws (else None, so the game gets the click). It draws the row, free-placed items and the open folder at Icon Size, keeps each hidden real icon's `Location` where its picture is (so menus/windows anchored to it open there) and forwards input with `TriggerMouseInput`: left press+release together on release (a drag never presses an icon), right press/release as they happen (Blish opens a control's `Menu` on right press). Shift+right-click an icon or right-click a folder raises `MenuRequested`. Hidden controls get no Update, so Blish never clears a real icon's `MouseOver`: `IconRegistry.EndHover` sets it false by reflection when the hover moves off, so `MouseEntered` fires on the next hover. With Blish HUD's `--debug`, the module adds one `GameService.Debug.OverlayTexts` line per icon (key, module, place, alert/loading), and each identification is logged at Debug. An open folder closes only on its own icon or a press on the game (`Mouse.ActiveControl` null), never on clicking its icons or a Blish HUD menu or window. Alerts: a closed folder holding an icon with Blish HUD's `logo-update` badge (`LiveIcon.ShowsUpdateAlert`, by texture reference) or whose module changed its picture since it was identified (`PictureChanged`: `Icon` vs `UsualIcon`, compared by inner texture; Event Table's error icon, Clears Tracker's notification) draws it small in its bottom right corner, a spinner below it while any icon in it has a `LoadingMessage`, and names them in its tooltip. Uses global mouse events for presses/releases; drags start after 6 px unless Lock Icons.
- `LayoutStore` saves `blishiconmanager/layout.json`: `row` (keys and `folder:<guid>`), `free` (id → x, y), `removed`, `folders` (name, icon spec, direction, items, `columns` × `rows` grid, `cells` key → column/row, `iconSize`), `names`, `sizes` (id → px; else Icon Size) and `hoverPictures` (folder id → spec; a folder's icon is its `icon`). An id is in at most one place; the index passed to `PlaceInRow` is counted without the moved item. Folder icons sit in free cells (gaps allowed); `PlaceInFolder` takes the first free cell nearest the folder, `PlaceInFolderAt` a given one (swapping, or moving the occupant to a free cell), and a full grid grows by a line on its expand side (`Grow`; up/left shift existing cells). While an icon is dragged to a full open folder, `IconLayer` shows that extra line for the whole drag (`FolderGeometry`), so the panel never resizes mid-drag. Older files' folders get a grid on load (`FitGrid`). New keys are inserted into the row by Blish's priority order. Saved 1 s after the last change and on unload.
- With `fs.bagofholding` enabled (checked on the first Update, before any icon is touched, then every 2 s), it notifies the player and disables itself via its `ModuleManager.Disable()`, queued with `Overlay.QueueMainThreadUpdate` (not called from inside its own Update).
- `NexusLink` reads Nexus's `DL_NEXUS_LINK_<gw2 pid>` shared memory as Freesnow's Nexus Shim does (at byte 40: icon count, mode, vertical; offset = (int)(35.3 × (n + 1)) + 2, n = count in extend mode, 1 if vertical, else 0), used in place of `LeftOffset` while Make Room for Nexus is on, unless the `fs.nexusshim` module is enabled.
- `FolderIcons` resolves a picture spec (`default`, `preview`, `arrow`, `asset:<id>`, `file:<png in blishiconmanager/icons>`, `icon:<key>`; the first three for folders only) and draws folders. `arrow` is the squad list's expand arrow as Kenedia's QoL hotbar uses it (155906/155907 left dim/bright, 155909/155910 right, 155929 down, flipped for up): pointing the way the folder opens, back while open. An icon or folder without a hover picture grows by an eighth about its middle while lit (`FolderIcons.Grown`). `IconPicker` chooses a folder's icon and hover icon (player-facing text says "icon", never "picture"; the saved `hoverPictures` key and `picture:` icon keys keep their names). Corner icons can't be given another icon: they're always drawn as their modules give them, so their alerts show; a file's old `pictures` and corner-icon hover entries are dropped on load. It and `SliderPopup` are `MovablePanel`s, dragged by the title bar. `IconsList` is the Icons and Folders lists in the settings window (`SettingsSection.BuildExtra`), rebuilt at most once a frame and not while a `ValueSlider` is dragged or a box typed in; sizes and grids are `ValueSlider`s there and in `SliderPopup`, which the right-click menus open.
